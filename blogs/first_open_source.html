My first open-source contribution

How a confusing error in Django turned into my first merged pull request.

Fine. I'll fix it myself!

Contributing to a project as big as Django can feel intimidating. The codebase is huge, the maintainers know it inside out, and you're hoping your pull request doesn't break anything important. But open source runs on collaboration, and my first real contribution taught me exactly that.

The bug: ticket #36271

While going through Django's issue tracker, I found ticket #36271. If you created a template directly in code and it used a relative path, Django crashed with an error that had nothing to do with the real problem:

Template("{% extends './base.html' %}")

AttributeError: 'NoneType' object has no attribute 'lstrip'

A template made like this has no file location (Django calls it an unknown origin), so there's nothing to resolve ./base.html against. The error should have said that. Instead, it pointed somewhere else entirely.

Writing the fix and the tests

Setting up Django locally was the first hurdle. Its test suite is large, and getting it running meant reading the contributing guide carefully. Once the tests passed on my machine, I traced the error back to django/template/loader_tags.py.

The fix itself was only a few lines: check for the missing template name and raise a clear TemplateSyntaxError instead. But writing the fix was only half the job. I also had to write tests that prove the bug is gone and stop it from coming back.

The hardest part wasn't writing the code. It was making sure the fix held up for thousands of developers.

The review

Within a few days, Sarah Boyce, a Django Fellow, reviewed my pull request. She asked for one change to how the test was structured. I pushed the update, the checks went green, and on 24 March 2025 it was merged as pull request #19295.

Seeing my code become part of a framework that so many developers use is something I won't forget. I also wrote a more technical version of this story on Medium.
