Implementing the WHATWG DOM in C++

Every web page becomes a tree of nodes inside your browser. I built that tree, and the rules around it, from the official spec.

It's all a tree!

Web developers rarely think about the Document Object Model. You call document.getElementById() and an element comes back. Implement the DOM yourself, in C++, and you find out how much the WHATWG DOM Living Standard asks for behind that one call.

My project, Webelo, is a DOM library and HTML visualizer written in C++. The goal isn't just to parse HTML. It's to implement the data structures and algorithms exactly as the WHATWG specification describes them.

The spec is the truth. Everything else is an approximation.

The node tree

The core of the DOM is the node tree. In C++ that means careful memory management: every node keeps pointers to its parent, its children and its siblings, without creating cycles that leak memory. I implemented the full tree and leaned heavily on preorder depth-first traversal.

// Preorder depth-first traversal in Webelo
void traverseDOM(Node* root) {
    if (!root) return;

    // Process the current node first
    process(root);

    // Then each child, in order
    for (Node* child : root->childNodes) {
        traverseDOM(child);
    }
}

Preorder traversal visits elements in the same order they appear in the document. It's also what queries like querySelector are built on.

Events

Next came event dispatch. In the spec, an event like a click doesn't just happen at one node. It travels down the tree (the capture phase), reaches its target, then bubbles back up. Implementing addEventListener and dispatchEvent in C++ meant building that whole path so it follows the WHATWG flow step by step.

What's next

Webelo is the first layer of a browser I want to build; parsing and rendering come next. The code is on GitHub, the docs are at webelo.onrender.com, and you can try the visualizer in your browser.
